# 列名映射与脏数据参考

## 1. 标准列

`normalize_sheet.py` 输出固定六列：

| 标准列 | 必填 | 下游用途 |
|---|---|---|
| `公司` | ✅ | 看板分栏、去重 key 的一部分 |
| `岗位名称` | ✅ | 卡片标题、关键词匹配主字段 |
| `岗位页链接` | 建议 | 扫描与投递的入口；为空则该行只能浏览 |
| `城市` | 否 | 地域筛选；多值用 `、` 或 `/` 分隔，取第一个作为主城市 |
| `职责族` | 否 | 分组标签，不影响筛选 |
| `来源校招页` | 否 | 溯源，便于回溯到原始招聘页 |

## 2. 已支持的列名别名

匹配时会先做归一化：去首尾空白、去括号注释（`（全称）`）、去标点、转小写。

| 标准列 | 常见写法 |
|---|---|
| 公司 | 公司、公司名称、公司全称、公司简称、企业名称、企业、单位、用人单位、招聘单位、雇主、机构名称、所属公司、company、employer、organization |
| 岗位名称 | 岗位名称、岗位、岗位名、职位名称、职位、职位名、招聘岗位、招聘职位、job title、position、title、job |
| 岗位页链接 | 岗位页链接、岗位链接、岗位地址、职位链接、详情链接、投递链接、网申链接、网申地址、申请链接、报名链接、链接、网址、url、link、apply url、job url |
| 城市 | 城市、工作城市、工作地点、地点、所在地、工作地址、上班地点、base 地、city、location、工作地区、地区 |
| 职责族 | 职责族、职能、职能类别、岗位类别、职位类别、职位族、方向、大类、类别、category、function、job family |
| 来源校招页 | 来源校招页、来源、来源网站、来源页面、招聘渠道、渠道、信息来源、source、channel |

遇到表里没有的列名，两种处理：

1. 在 `scripts/normalize_sheet.py` 的 `ALIASES` 字典里补一条（推荐，一次改动长期生效）；
2. 先手工把表头改成标准列名，再跑脚本。

## 3. 常见脏数据与脚本行为

| 形态 | 脚本行为 |
|---|---|
| 表头不在第 1 行（上面有标题、日期、公司 logo 行） | 自动在前 15 行里找命中列名最多的一行；也可 `--header-row N` 强制指定 |
| 多 sheet（总表 + 分城市） | 选「行数 × 表头命中数」得分最高的那个；也可 `--sheet 名称` 指定 |
| 合并单元格导致的空值 | 只影响该行；`公司`/`岗位名称` 为空的行会被丢弃并计入统计 |
| 「合计 / 小计 / 备注」行 | 按前缀正则识别并丢弃 |
| 链接是 Excel 超链接对象而非文本 | 读单元格 `hyperlink.target`，优先于文本 |
| 链接是 `www.xxx.com/...` 无协议 | 自动补 `http://` |
| 同一岗位重复出现（多个城市分行） | 按 `公司 + 岗位名称 + 链接` 去重，保留首次出现 |
| 岗位名里有换行 / 制表符 | 折叠为单个空格，截断到 160 字 |
| 城市是多值 `上海、北京` | 原样保留；下游用第一个作为主城市 |
| 身份证、手机号等个人信息列 | 不读取、不输出（只取六列白名单） |

## 4. 筛选口径

`filter_positions.py` 与 `resume-bot/backend/positions.py` 保持一致：

- 关键词匹配范围 = `岗位名称 + 城市 + 职责族 + 公司` 拼成的整块文本
- `strict`：**所有**关键词命中 **且** 城市命中
- `loose`：**任一**关键词命中 **且** 城市命中
- `all`：不过滤

输出多一列 `匹配等级`（`strict` / `loose` / `none`），按 strict → loose → none 排序。

脚本还会单独提示「关键词只在公司/城市/职责族里命中、标题本身不含」的条目 ——
这类岗位容易被误当成目标岗位，需要人工看一眼。

## 5. 长度与规模

- 单表 5000 行以内处理时间可忽略（openpyxl 普通模式）
- 超过 5 万行建议先拆城市/职能分表，或改用 `read_only=True` 的流式读法
- 输出文件默认与被转换文件同目录
