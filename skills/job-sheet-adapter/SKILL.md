# 职位表适配器

## 用途

招聘网站导出的职位表列名五花八门（「企业名称 / 单位 / 公司全称」「工作地点 / base 地 / city」），
而下游程序只认六列固定字段。本 skill 做两件事：

1. **归一化**：任意表头 → 标准六列，顺带清洗链接、去重、剔除合计行。
2. **筛选**：按关键词与城市，输出 strict / loose 两档结果。

产出可直接放进 resume-bot 项目根目录，命名为 `岗位总表.xlsx`，后端启动即读取。

## 何时使用

- 用户上传 `.xlsx` / `.xlsm` / `.csv` 职位表，要求"整理""转换""变成程序能用的格式"
- 用户给出关键词与城市，要求"筛一下""只看符合的"
- 用户要做岗位分栏看板，但表格列名不匹配

不适用：招聘网站页面抓取（那是 `filler.py` 的 `scan` 能力）、简历解析。

## 工作流

### 第 0 步：确认输入

先确认三件事，缺哪件问哪件（不要一次问完）：

- 文件路径
- 哪一列是「公司」、哪一列是「岗位名称」（若表头明显可跳过此问）
- 筛选条件：关键词、目标城市

用 Read 或 `openpyxl` 快速看一眼前 5 行，确认表头在第几行、有没有多 sheet。
不确定时直接跑脚本，它会自动探测并在摘要里报告识别结果。

### 第 1 步：转标准格式

```bash
python scripts/normalize_sheet.py "<输入文件>" -o 岗位总表.xlsx
```

可选参数：

| 参数 | 用途 |
|---|---|
| `--sheet 名称` | 指定工作表（默认自动挑最像岗位表的） |
| `--header-row N` | 表头在第 N 行（默认自动探测前 15 行） |
| `--strict-url` | 没有链接的行直接丢弃 |
| `--json` | 只输出 JSON 摘要，便于程序处理 |

### 第 2 步：读摘要并核对

脚本会打印：识别到的列映射、缺失的标准列、保留/丢弃条数、覆盖城市、警告。

必须处理的情况：

- **缺 `岗位页链接`** → 明确告诉用户"这张表只能浏览，无法自动投递"，不要假装能投
- **缺 `城市`** → 地域筛选不可用，询问是否要手工补一列
- **大量行被丢弃** → 打印的 `dropped` 里会分「缺公司 / 缺岗位名 / 重复」，据此判断是表头认错还是数据本身不全

### 第 3 步：筛选

```bash
python scripts/filter_positions.py 岗位总表.xlsx \
  --keywords 产品经理 本科 \
  --cities 杭州 上海 北京 \
  --mode strict
```

- 已有 `match_rules.json` 时用 `--rules match_rules.json` 代替 `--keywords/--cities`
- `--mode strict`（默认）= 关键词全含且城市命中；`loose` = 任一含；`all` = 不过滤
- 输出文件名默认 `<输入名>_筛选.xlsx`，多一列 `匹配等级`

### 第 4 步：交付

向用户报告四件事，缺一不可：

1. 保留多少条、丢弃多少条、为什么丢
2. 识别到的列映射（让用户能判断有没有认错）
3. 筛选后各档数量（strict / loose）
4. 输出文件的绝对路径

**不要把整张表贴进对话**。给路径 + 统计 + 前 3 条样例即可。

## 硬性规则

- **不编造链接**。原表没有 URL 就留空，绝不用搜索补一个"看起来对"的地址。
- **不补写岗位信息**。公司名、岗位名缺失的行直接丢弃，不要根据上下文猜。
- **不改原文件**。只写新文件，默认与输入同目录。
- **只输出六列白名单**。原表里的手机号、身份证、内推码等列一律不读入结果。
- **中文表头优先**。若表头是中英混排，以中文列为准；英文别名仅在缺失时兜底。

## 常见故障

| 现象 | 处理 |
|---|---|
| `无法识别表头` | 用 `--header-row N` 指定；或把表头改成标准列名 |
| `缺少必需列：公司` | 该表可能没有公司列（单公司招聘页导出），用 `--header-row` 后手工补，或询问用户 |
| 城市列识别成「工作地址」导致筛选不中 | 手工指定：把该列名改为 `城市`，或提示用户表里有更精确的城市列 |
| 输出 0 条 | 看 `dropped` 分布；多半是表头行选错，导致整表被当成数据 |
